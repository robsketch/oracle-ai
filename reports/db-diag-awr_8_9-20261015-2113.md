### 🔵 INFO: Low execute-to-parse ratio (31.8%) and library hit 93.7%, caused by background jobs
- **Evidence:** Parses 11.3/s against executes 16.6/s. Top parse-call statement is
  `7qb74y7hp6cwd` (auto-task scheduler control query, CDB$ROOT, 7,426 parses for 7,427 execs,
  18.1% of all parse calls). Next come `sensitive_fixed$` lookups (1,687), the
  `vecsys.vector$index` poll `4zxrh77d4v3vj` (about 1,436 per container) and
  `sys$bsg_timeout` `SELECT :B1` (1,360 per container). Soft parse is still 96.8%, so these are
  cheap soft parses, not hard ones.
- **What it means:** "Execute to parse" is the share of executions that reused an already-open
  cursor without parsing again. Background PL/SQL here parses once per execution (soft parse,
  meaning the plan is found in the shared pool and not recompiled). With so little load, these
  ratios are dominated by internal polling and don't point to an application problem.
- **Recommendation (not executed):** None for this window. Recheck parsing in a window with
  real application load. If soft parse drops below 95% there, look for literal SQL.

## Method

- **File mode:** the skill's file-mode rule applies because the argument was a path. Ran
  `python3 -I .claude/skills/db-diag-review/extract_report.py reports/awr/awr_8_9.txt` and
  analysed the extract (25 sections found). The raw file wasn't read. Preflight and MCP
  steps were skipped, so no database connection was made and no SQL was sent.
- **Workload source:** an existing AWR text report. Reading an AWR report file is always
  allowed. The header also shows Edition FREE, where the Diagnostics Pack is included (see
  `LICENSING.md`). No ASH/ADDM queries or Tuning Pack.
- **Choices made without asking:** (1) The `--days` filter wasn't used because it doesn't
  apply to AWR. (2) AWR snapshot times are treated as UTC (container DB clock). (3) Areas
  that need the alert log, incidents or traces are shown as "n/a" and don't count toward the
  overall status. (4) The extractor reported no match for "Top Timed Events" (26ai calls it
  "Top 10 Foreground Events", which it did capture) or for "Complete List of SQL Text". The
  truncated SQL texts in the extract were enough to identify every top statement.
- **Caveats:** a single hourly AWR window on an idle box. The ratings describe health at rest,
  not under load. AWR in this CDB is instance-wide (CDB$ROOT + PDBs).
- **Audit:** no MCP sessions were opened in this run. In MCP mode, sessions are tagged
  `SQLcl-MCP` in `V$SESSION`, and `DBTOOLS$MCP_LOG` isn't written for the read-only `dbmon`
  users.
